# The superlinear guide

How a project that superlinear works on is built, from an issue in Linear to a build in TestFlight. Projects link to these pages from their READMEs. Link to a section by its anchor in [Anchors](anchors.md), which stays the same when a heading changes.

| Page | Contents |
| --- | --- |
| [The life of an issue](lifecycle.md) | Selection and the ready gate, the agent, the pull request, reviews, conflicts, the merge, completion. |
| [Planning](planning.md) | Proposals and trust levels, the planning job, follow-ups from agents, the standup, project updates. |
| [Bootstrap](bootstrap.md) | Components, manifests, secrets and where they come from, Needs human steps, `bootstrap --check`. |
| [Builds](builds.md) | CI, staging and TestFlight builds, build numbers, the release rule, TestFlight feedback. |
| [Configuration](configuration.md) | Every config key, and the files superlinear reads and writes. |
| [Operations](operations.md) | Installing and running the daemon: restarts, disk space, `superlinear status`, make targets, releases. |
| [Anchors](anchors.md) | The stable anchors other repositories link to. |

Sections for features that are not built yet say so in one line, with the issue that builds the feature.
